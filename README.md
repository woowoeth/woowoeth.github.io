# 人类世界生存法则 · Human World

一个关于「世界到底怎么运转」的知识库：从谋略、权力、财富到心智、关系、身心，
取自 **115 位人物与典籍**，跨越 2600 年。

线上： https://ourword.ai/

每个条目写清楚四件事：这个人真正留下的那一个想法、背后的故事、拆开的分则与例子、
今天怎么用。条目之下另有 **258 篇深度阅读**。

|---|---|
| 谋略与竞争 | 16 |

| 创业与产品 | 16 |

| 学习与成长 | 7 |
| 身心与生活 | 3 |
| 家庭与关系 | 6 |

分类曾是七类，其中「典籍·洞见」是形式不是领域，成了杂物筐（《国富论》《乌合之众》
《史记》都在里面，而同为书的《孙子兵法》却在战略）。现已按领域拆成十类；旧路径保
留跳转桩。

**一个类别少于 3 个条目就不生成主题页**（`hub_min`），否则 `/t/<slug>/` 会成为死链。
新开一个领域时要一次凑够 3 个。

## 数据在哪

单文件应用，唯一真源是 `index.html` 里的 `const D=[...]`。每条包含：

`c` 领域 · `n` 名字 · `e` 年代 · `w` 关键词 · `y` 排序年份 · `d` 简介 · `story` 经典一幕 ·
`f` 核心框架（`n`/`d`/`eg`）· `q` 金句 · `apply` 现代应用 · `l` 关联 · `contrast` 对照阅读

关联与对照单向手写即可，渲染期自动补反向边。**但只能指向已存在的条目**——指向下一批
才写的人会生成死链，完整性检查会拦住。

深度阅读（章节层）**不进 `D[]`**，每个条目一个文件放在 `seo/chapters/<slug>.py`，
含 `PARENT` 与 `CHAPTERS`。正文里 `==这样==` 渲染成红色重点。

## 首页发现层

首页顶部那一整块由 `scripts/force_chapter_ui.py` 注入，标记块 `<!--HWX:FIND-->`
幂等替换，锚点是 `<div class="tabs" id="tabs"`（这个 div 保留在 DOM 里当锚点，不可删）。

包含：

- **今日三样**：金句 / 一篇 / 一问，按本地时区午夜翻牌，可保存为分享卡
- **按处境找**：50 个处境 × 114 个问题 × 228 条答案，定义在 `scripts/hwx_scenes.py`。
  场景名只说处境，问题在点开后出现。默认展开第一个，所以前五个必须是最高频的
- **最新 / 全部** 两个 feed：瀑布流混排人物卡、竖排金句卡、问题卡
- **搜索**：覆盖人名、介绍、章节、正文，外加一张口语映射表
  （睡不着 → 瑞迪/纽波特/塞涅卡），因为用户搜的是口语，内容写的是书面语

## 新增条目的收录标准

三条否决项，缺一不收：

1. **能填满 apply 块**（局面 / 先问 / 用反了）。填不出说明只有感悟没有方法
2. **至少 2 条引语能指到具体出处**。全是流传语录的不收
3. **核心主张不与现有条目重合**，除非提供明显不同的适用条件或角度

三条优先级项：**扇出 ≥4 个处境**（一条原理能罩住多少局面）、**有可讲的具体事**、
**有实证或经过时间检验**。

按扇出选，不按名气：「课题分离」能挂十几个处境，「取食于敌」只能挂两三个。

## 构建顺序

CI（`.github/workflows/seo.yml`）严格按此顺序：

```bash
python scripts/patch_geo_seo.py     # 在 stock geo_kit 上叠 GEO 增强，幂等
python scripts/apply_redesign.py    # 条目页样式覆盖、slug 映射
python seo/build_seo.py             # 生成全部静态页与索引产物
python scripts/force_chapter_ui.py  # 注入首页发现层、章节 UI、主题按钮
python scripts/check_integrity.py   # 完整性闸门
```

分享图由 `scripts/gen_og.py` 一次性生成（**不在 CI 链里**），新增章节后要手动重跑。

## 完整性闸门

`scripts/check_integrity.py`，每条规则都对应一次真实事故：

| 检查 | 曾经发生的事 |
|---|---|
| 条目必须有章节 | 加了 6 个条目没写章节，条目页没有「深度阅读」，也进不了「最新」 |
| 章节的归属条目必须存在 | rebase 取了远端 index.html，D 数组退回旧版而章节文件还是新的，覆盖数看着正常 |
| 条目必须有手写介绍 | 介绍数悄悄停在 100，而条目已经 106 |
| 章节必须有分享图 | 分享图数停在 228，而章节已经 240 |
| 关联只能指向已有条目 | `l`/`contrast` 指向下一批才写的人，生成死链 |
| 类别达标才进 slug 表 | 类别只有 1-2 个条目却生成了链接，主题页不存在 |
| 条目必须有英文 slug | 否则生成中文路径 URL |
| 二维码必须可解码 | 换图时可能换坏 |
| 信息流卡片不得重复 | 取句写成 `(i*53) % 池大小` 而池子正好 53 条，所有金句卡是同一句 |

每条都用故障注入验证过确实会报错，不是写完就算数。

## 三条硬规矩

- **不要直接改 `geo_kit.py`**——CI 会从固定 commit 拉回来覆盖。改动写进 `scripts/patch_geo_seo.py`
- **不要从 `hw_theme.py` 的模板里删 `%s`**——参数元组不会跟着变，构建会崩
- **改源头不要改产物**——`index.html` 是构建产物也是数据源，改数据改 `D[]`，
  改样式和逻辑改 `scripts/force_chapter_ui.py`

## rebase 冲突怎么处理

CI 每次构建后会自己提交一版产物，本地推送常遇到冲突，且冲突文件几乎总是 `index.html`。
它既是产物又是数据源，逐行 merge 无意义。做法：取远端版本作底，**重新注入本批新条目**，
再重跑构建。直接 `checkout --ours/--theirs` 会静默丢数据——完整性闸门的反向检查就是为
这个加的。
