# 人类世界生存法则 · Human World

一个关于「世界到底怎么运转」的知识库：从谋略、权力、财富到心智、关系、身心，
取自 **131 位人物与典籍**，跨越 2600 年。

线上： https://ourword.ai/

每个条目写清楚四件事：这个人真正留下的那一个想法、背后的故事、拆开的分则与例子、
今天怎么用。条目之下另有 **290 篇深度阅读**。

| 领域 | 条数 |
|---|---|
| 谋略与竞争 | 16 |
| 权力与组织 | 19 |
| 财富与风险 | 16 |
| 创业与产品 | 17 |
| 识人与相处 | 13 |
| 心智与情绪 | 13 |
| 学习与成长 | 10 |
| 身心与生活 | 6 |
| 家庭与关系 | 10 |
| 世界如何运转 | 11 |

分类曾是七类，其中「典籍·洞见」是形式不是领域，成了杂物筐（《国富论》《乌合之众》
《史记》都在里面，而同为书的《孙子兵法》却在战略）。现已按领域拆成十类；旧路径保
留跳转桩。

**一个类别少于 3 个条目就不生成主题页**（`hub_min`），否则 `/t/<slug>/` 会成为死链。
新开一个领域时要一次凑够 3 个。

## 数据在哪

单文件应用，唯一真源是 `index.html` 里的 `const D=[...]`。每条包含：

`c` 领域 · `n` 名字 · `e` 年代 · `w` 关键词 · `y` 排序年份 · `d` 简介 · `story` 经典一幕 ·
`f` 核心框架（`n`/`d`/`eg`）· `q` 金句 · `apply` 现代应用 · `l` 关联 · `contrast` 对照阅读

关联与对照单向手写即可，渲染期自动补反向边。**但只能指向已存在的条目**——指向下一批
才写的人会生成死链，完整性检查会拦住。

深度阅读（章节层）**不进 `D[]`**，每个条目一个文件放在 `seo/chapters/<slug>.py`，
含 `PARENT` 与 `CHAPTERS`。正文里 `==这样==` 渲染成红色重点。

## 首页发现层

首页顶部那一整块由 `scripts/force_chapter_ui.py` 注入，标记块 `<!--HWX:FIND-->`
幂等替换，锚点是 `<div class="tabs" id="tabs"`（这个 div 保留在 DOM 里当锚点，不可删）。

包含：

- **今日三样**：金句 / 一篇 / 一问，按本地时区午夜翻牌，可保存为分享卡
- **按处境找**：87 个处境 × 341 个问题 × 682 条答案，定义在 `scripts/hwx_scenes.py`，
  每个处境带一个 `g` 字段归入 14 个组。首页只留一行入口，点它切到「处境」tab——
  就地展开的标签目录已废弃（占 1049px，且 100% 与信息流内容重复）
- **最新 / 全部 / 处境** 三个 tab：前两个是瀑布流混排人物卡、竖排金句卡、问题卡，
  第三个是 341 张问题卡，复用同一套 `.kc` 卡片样式
- **搜索**：覆盖人名、介绍、章节、正文，外加一张口语映射表
  （睡不着 → 瑞迪/纽波特/塞涅卡），因为用户搜的是口语，内容写的是书面语

## 新增条目的收录标准

三条否决项，缺一不收：

1. **能填满 apply 块**（局面 / 先问 / 用反了）。填不出说明只有感悟没有方法
2. **至少 2 条引语能指到具体出处**。全是流传语录的不收
3. **核心主张不与现有条目重合**，除非提供明显不同的适用条件或角度

三条优先级项：**扇出 ≥4 个处境**（一条原理能罩住多少局面）、**有可讲的具体事**、
**有实证或经过时间检验**。

按扇出选，不按名气：「课题分离」能挂十几个处境，「取食于敌」只能挂两三个。

## 数据结构

四层，每一层由上一层派生，唯一真源是 `index.html` 里的 `const D=[...]`。

```
条目  D[]                    131 个   index.html 的 D 数组
 └─ 章节  seo/chapters/*.py  290 篇   一个条目一个文件，PARENT + CHAPTERS
      └─ 处境  hwx_scenes.py   87 个   场景名 → 问题 → 答案(slug, k)，15 个组
           └─ 问题            341 条   首页「今日一问」、信息流问题卡、处境 tab 共用
                └─ 答案       682 条   指向具体章节
```

**层与层之间由闸门强制，不靠记性：**

| 关系 | 由谁强制 | 规则 |
|---|---|---|
| 条目 ↔ 章节 | `check_integrity.py` | 双向：条目必须有章节，章节的归属条目必须存在 |
| 章节 → 处境 | `check_coverage.py` | 每个条目至少一篇章节被问题引用；领域覆盖 ≥40%；全站 ≥70% |
| 问题本身 | `check_questions.py` | 内容运营标准，见下 |

## 补内容的规程

**加条目时，这四样必须同时补齐**，缺一构建就失败：

1. `index.html` 的 `D[]` —— 条目本体（`l`/`contrast` 只能指向已存在的条目）
2. `seo/chapters/<slug>.py` —— 至少一篇章节
3. `scripts/hwx_scenes.py` —— **给新章节挂上问题**，并入现有处境或新开一个
4. `scripts/force_chapter_ui.py` 的 `HWX_INTROS` —— 首页卡片的手写介绍

外加手动跑一次 `scripts/gen_og.py` 生成分享图（它不在 CI 链里）。
macOS 上没有 Noto Serif CJK，脚本会自动退到 Songti SC Bold 并**只补缺失的图**，
不重画已有的——新旧字形会有差异，要统一得在装了 Noto 的机器上跑 `--all`。

**写 `q`（金句）时有一条容易掉进去的坑：三条不能都是从正文摘的。**
`hw_theme` 会丢掉与正文重复的金句（它的注释写着「100 个条目里有 55 个把分则
开头那句又在文末列一遍」），三条全被丢光时，整个「金句」段不渲染——页面上
一个字都没有。2026-09-01 普查发现 128 个条目里 27 个中招。现在由
`check_integrity` 的第 6c 条拦住：新增条目再犯直接失败，存量挂在
`LEGACY_NO_QUOTES` 里，**那张表只许变短**。

章节页的 FAQPage 由 `seo/hw_chapters.py` 的 `_faq_ld()` 自动生成，
材料全部取自已有字段——`dek` 后半句是问题、`f[]` 每条分则是问答对、
`apply` 的「局面 / 先问 / 用反了」凑一条。**新增章节自动就有，不需要额外动作。**
中位 5 条问答，全站 290 篇共 1449 条。

章节层另有一套硬约束（`check_chapters`）：`dek` 25-70 字、`story` 80-190 字、
≥3 条分则且每条 `d` 35-110 字、`apply` 恰好「局面/先问/用反了」三段、
金句恰好 3 条、至少一处 `==标红==`。

第 3 条最容易漏，也最致命：条目和章节写好了，但处境层没挂上，**用户没有任何
路径能走到它**。曾经出现过 9 个家庭与关系的条目全部写完、处境层一个都挂不上，
以及费曼、艾利克森、波普尔等 12 个条目长期失联的情况——内容存在却完全不可达。

## 问题卡的内容运营标准

问题池是整个站最靠前的一层——它是首页「今日一问」和信息流问题卡的共同来源。
问题本身不戳中人，卡片设计得再好都白搭。标准由 `scripts/check_questions.py` 强制：

**问题必须是当事人此刻会对自己说的那句话，不是一个可以拿去查资料的题目。**

| 否决项 | 反例 | 正例 |
|---|---|---|
| 查资料语气（怎么/如何开头） | 怎么让自己迈出第一步？ | 我知道该做，可就是动不了。 |
| 抽象名词堆的分析题 | 什么样的资产才是真正的资产？ | 钱放着不动，我心里发慌。 |
| 无人称无情境 | 砍掉哪些才是对的？ | 全都重要，我砍哪个都疼。 |
| 长度 8-18 字 | —— | 短了撑不起情境，长了一眼读不完 |

这套标准建立时，原有 114 条里 **58% 不合格**——全部重写过一遍。

首页一问取的是这个池子（`QQ`），不是每篇 apply 里的「先问」句（`ASK`）。
后者是给读完文章的人自省用的，主语是读者、往往三连问，放到首页会变成考卷。

## 构建顺序

CI（`.github/workflows/seo.yml`）严格按此顺序：

```bash
python scripts/patch_geo_seo.py     # 在 stock geo_kit 上叠 GEO 增强，幂等
python scripts/apply_redesign.py    # 条目页样式覆盖、slug 映射
python seo/build_seo.py             # 生成全部静态页与索引产物
python scripts/force_chapter_ui.py  # 注入首页发现层、章节 UI、主题按钮
python scripts/check_questions.py   # 问题卡内容标准
python scripts/check_coverage.py    # 处境层覆盖
python scripts/check_integrity.py   # 完整性闸门
```

分享图由 `scripts/gen_og.py` 一次性生成（**不在 CI 链里**），新增章节后要手动重跑。

## 完整性闸门

`scripts/check_integrity.py`，每条规则都对应一次真实事故：

| 检查 | 曾经发生的事 |
|---|---|
| 条目必须有章节 | 加了 6 个条目没写章节，条目页没有「深度阅读」，也进不了「最新」 |
| 章节的归属条目必须存在 | rebase 取了远端 index.html，D 数组退回旧版而章节文件还是新的，覆盖数看着正常 |
| 条目必须有手写介绍 | 介绍数悄悄停在 100，而条目已经 106 |
| 章节必须有分享图 | 分享图数停在 228，而章节已经 240 |
| 关联只能指向已有条目 | `l`/`contrast` 指向下一批才写的人，生成死链 |
| 类别达标才进 slug 表 | 类别只有 1-2 个条目却生成了链接，主题页不存在 |
| 条目必须有英文 slug | 否则生成中文路径 URL |
| 二维码必须可解码 | 换图时可能换坏 |
| 写了 fail/lesson 就必须渲染出来 | 23 个条目 4525 字的「败局时刻」躺了两周，没有任何渲染器读它 |
| 写了金句就必须渲染出金句段 | 三条全从正文摘，被 hw_theme 丢光，整段消失（128 个里 27 个）|
| 信息流卡片不得重复 | 取句写成 `(i*53) % 池大小` 而池子正好 53 条，所有金句卡是同一句 |

每条都用故障注入验证过确实会报错，不是写完就算数。

## 交接

`HANDOVER.md` —— 给下一个接手的 AI 代理：当前状态、这一轮做了什么及原因、
接下来的计划、用户场景思考、已废弃的计划（重要，别捡回来）、工作纪律。
接手时先读它。

## 视觉规范

`DESIGN.md` —— 色板、字体层级、组件规格、断点，**全部是线上实测值**，
外加一节「该做与不该做」，每条对应一次真实事故（竖排字体糊掉、655KB 字体拖慢首屏、
正则删 DOM 块导致整页边距消失、条目名含空格生成死链）。

改样式前先读它；改完回来更新。数值有出入时以浏览器实测为准。

## 三条硬规矩

- **不要直接改 `geo_kit.py`**——CI 会从固定 commit 拉回来覆盖。改动写进 `scripts/patch_geo_seo.py`
- **不要从 `hw_theme.py` 的模板里删 `%s`**——参数元组不会跟着变，构建会崩
- **改源头不要改产物**——`index.html` 是构建产物也是数据源，改数据改 `D[]`，
  改样式和逻辑改 `scripts/force_chapter_ui.py`

## rebase 冲突怎么处理

CI 每次构建后会自己提交一版产物，本地推送常遇到冲突，且冲突文件几乎总是 `index.html`。
它既是产物又是数据源，逐行 merge 无意义。做法：取远端版本作底，**重新注入本批新条目**，
再重跑构建。直接 `checkout --ours/--theirs` 会静默丢数据——完整性闸门的反向检查就是为
这个加的。
